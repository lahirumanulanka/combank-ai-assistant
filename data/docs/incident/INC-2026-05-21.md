# Bill payment failures - idempotency cache eviction

**Incident ID:** INC-2026-05-21 · **Severity:** SEV3 · **Service:** mobile-payments · **Date:** 2026-05-21 · **Duration:** 45 minutes

## Timeline
- 19:30 - Customers report duplicate or failed transfers.
- 19:34 - Alert fires; on-call engineer acknowledges.
- 19:37 - Incident declared SEV3.
- 20:00 - Increased Redis memory.
- 20:00 - Reversed the duplicate payments.
- 20:15 - Incident resolved; monitoring continued for 2 hours.

## Impact
About 900 bill payments were rejected and 40 were posted twice; all were fixed the next day.

## Root cause
Idempotency keys are stored in a shared Redis cluster with `maxmemory-policy allkeys-lru`. Month-end bill payment volume that filled Redis memory caused keys to be evicted early, so retried requests were not recognised: some transfers were posted twice and others were rejected with `IDEMPOTENCY_KEY_NOT_FOUND`.

## Resolution
Increased Redis memory. Reversed the duplicate payments.

## Follow-up actions
1. Move idempotency keys to a dedicated Redis cluster with `noeviction` and persistence.
2. Alert when Redis starts evicting keys.
