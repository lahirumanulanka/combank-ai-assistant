# Redis failover evicts idempotency keys - duplicate debits

**Incident ID:** INC-2026-09-27 · **Severity:** SEV2 · **Service:** mobile-payments · **Date:** 2026-09-27 · **Duration:** 35 minutes

## Timeline
- 11:05 - Customers report duplicate or failed transfers.
- 11:09 - Alert fires; on-call engineer acknowledges.
- 11:12 - Incident declared SEV2.
- 11:28 - Paused instant transfers for 10 minutes.
- 11:28 - Reversed the duplicate debits.
- 11:40 - Incident resolved; monitoring continued for 2 hours.

## Impact
528 customers were debited twice; all were refunded within 24 hours.

## Root cause
Idempotency keys are stored in a shared Redis cluster with `maxmemory-policy allkeys-lru`. A Redis primary failover followed by memory pressure on the new primary caused keys to be evicted early, so retried requests were not recognised: some transfers were posted twice and others were rejected with `IDEMPOTENCY_KEY_NOT_FOUND`.

## Resolution
Paused instant transfers for 10 minutes. Reversed the duplicate debits.

## Follow-up actions
1. Move idempotency keys to a dedicated Redis cluster with `noeviction` and persistence.
2. Alert when Redis starts evicting keys.
