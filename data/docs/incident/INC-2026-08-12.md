# Misconfigured retry policy after infrastructure migration

**Incident ID:** INC-2026-08-12 · **Severity:** SEV3 · **Service:** payment-gateway · **Date:** 2026-08-12 · **Duration:** 90 minutes

## Timeline
- 14:40 - Decline rate rises shortly after a deployment.
- 14:44 - Alert fires; on-call engineer acknowledges.
- 14:47 - Incident declared SEV3.
- 15:40 - Restored the retry policy.
- 15:40 - Audited all migrated configuration values.
- 16:10 - Incident resolved; monitoring continued for 2 hours.

## Impact
Short network blips turned into failed payments; about 1,700 payments failed.

## Root cause
After the move to the new Kubernetes cluster the gateway retry policy was 0 retries in production, while staging still had 3. Staging and production configuration had drifted apart because environment settings are edited by hand, and the difference was not caught before release.

## Resolution
Restored the retry policy. Audited all migrated configuration values.

## Follow-up actions
1. Keep environment configuration as code in git.
2. Add an automated drift check between staging and production.
