# Internal mTLS certificate expiry - API payments down 42 minutes

**Incident ID:** INC-2026-07-21 · **Severity:** SEV1 · **Service:** payment-gateway · **Date:** 2026-07-21 · **Duration:** 42 minutes

## Timeline
- 09:14 - Error rate jumps; logs show `SSL handshake failed`.
- 09:18 - Alert fires; on-call engineer acknowledges.
- 09:21 - Incident declared SEV1.
- 09:42 - Issued an emergency certificate from the internal CA.
- 09:42 - Deployed it to all gateway pods.
- 09:56 - Incident resolved; monitoring continued for 2 hours.

## Impact
All API payments failed for 42 minutes; about 31,000 payment attempts were rejected before posting. Post-incident review: MTG-2026-07-PIR.

## Root cause
The internal mTLS certificate between payment-gateway and the core banking adapter, which was missing from the Cert Register, expired. Certificates are renewed by hand using the Cert Register spreadsheet and there is no automated expiry alert, so nobody noticed in time. Connections failed with `SSL handshake failed: certificate has expired` (see RB-SEC-001 "Known gaps").

## Resolution
Issued an emergency certificate from the internal CA. Deployed it to all gateway pods.

## Follow-up actions
1. Automated certificate rotation with 30-day expiry alerts (owner: information-security).
2. Weekly scan for certificates that expire within 45 days.
